# Design

annals is an in-tray for AI agents: an agent publishes a document (text, a page, media, a folder) with one command and gets a link; the owner reads it on a phone. This page records the boundaries chosen before the first commit (the architecture-first seam table) and why.

## The one-command test

`annals publish README.md` prints a link, and `GET /docs` on the API over the same directory lists it (`/annals/api/docs` under `annals serve`, `/api/annals/docs` inside an enlace platform). That is v1, and `tests/test_cli.py` plus `tests/test_api.py` keep it true.

## Seams

| # | Seam | v1 default (no new dependency) | Replacement it was declared for |
|---|---|---|---|
| 1 | transport, `target=` (`annals.target`) | a local directory, or `host:/path` through the system `ssh` and `rsync` in batch mode | an http ingest endpoint with a bearer token, for agents with no ssh to the host. Not a third `Target`: a `Target` writes raw paths and the publisher authors `meta.json`, which an untrusted client must not. Ingest is a server-side publish entry point that receives the files and derives `id`, `files` and `kind` itself |
| 2 | auth, `authorizer=` (`annals.auth`) | none on localhost; cookie forwarded to an existing who-am-I endpoint plus an email allowlist; HTTP Basic | an OAuth or signed-token check, for a annals with API clients |
| 3 | data root | `~/.local/share/annals`, `ANNALS_DATA_DIR` | a `dol` store over blob storage, through the same `Target` verbs; the API reaches files only through `Target.local_path` (a blob target would answer `None`, and serving it then means one redirect to the store's URL at that call site) |
| 4 | base url for the printed link | `base_url` in the config file | per-target in the config |
| 5 | markdown rendering | `marked.js` in the browser, vendored | server-side rendering (or PDF) if the page ever needs to serve a non-browser reader |
| 6 | host, `mk_api` vs `mk_app` | mounted inside an app platform that owns login and routing (`mk_api` + a page shell); `annals serve` standalone otherwise | none needed: both exist |
| 7 | thumbnails, `thumbnailer=` | Pillow when installed, cached under the data root's `cache/thumbs`; else the original | a blob store's own image resizing, or poster frames for video via ffmpeg |
| 8 | what a directory publish skips, `exclude=` | `.*`, `__pycache__`, `*.pyc` | per-call patterns (`--all-files` keeps everything) |
| 9 | item sources, `mk_api(sources=)` (`annals.sources`) | the published documents plus named local folders read in place (`FolderSource`) | other personal-file folders; ledgers from several machines as one source over per-machine mirrors (see "Ledgers from several machines") |
| 10 | the owner's tags, `mk_api(tags=)` (`annals.tags`) | `JsonTagStore`: one JSON file under the data root | the database for app JSON (tw_platform#291) |
| 11 | how the page reaches items | `@zodal/store-http`'s `createHttpProvider` over `/items` (vendored, 7 KB) | the schema-driven zodal page (roadmap); any zodal `DataProvider` |

Surfaces: the CLI (`cw` over `annals/tools.py`), the Python API, MCP (`py2mcp` over string refs to the same functions), the shipped skill, and the FastAPI app. The CLI dispatches `annals.tools._dispatch_funcs`; `annals.tools.EFFECTS` classifies every function (`read`, `write`, `file`, `destructive`, `spend`, `server`) and a test fails on an unclassified one. MCP serves `tools_with(effects)`: by default read and write, so `purge` (`destructive`), `listen` (`spend`) and `aggregate --output` (`file`) need the host to ask (`ANNALS_MCP_EFFECTS=read,write,destructive`). The FastAPI app is the one exception: it has routes the CLI never will (thumbnails, raw files, the shell, the page's `/items`, `/sources` and `/tags` collections, `/audio`), and it keeps one reader-scoped family on purpose: listening state (`/listening/{id}`: what *this logged-in reader* has heard), which has no meaning for an agent on a command line. The operations an agent needs are functions in `tools.py` that the route calls or shares its core with: `purge` (`annals.catalog.purge_document`), `references` (`annals.references.collect`, one document, a group, or `--also` more), `listen` and `overview_state` (one overview, or `--also` several documents for one; `overview_state` is the read-tier poll), `aggregate`, and the exact filters of `ls` (`annals.docfilter`). The page's single-file export is `export` (one markdown file as `.md` or a titled `.pdf`; `aggregate` is the several-documents output with a table of contents) and the Share dialog's choices are `shareable`; the recipient-side `/shares/{token}/sources` stays HTTP-only. A new operation starts in `tools.py` and `EFFECTS`; a route that does the work itself is the gap to close.

NOT seams, written directly on purpose: the id format, the `meta.json` shape (the file; the result of `publish` and the rows of `ls` are a contract, see "The machine contract"), the bin semantics (a move), the page's framework (none), the sort keys, the full-text matching (every word, substring, over cached text), the facet counting (in the page, flat families), the date ranges.

## Decisions

**Python on PyPI.** The host that serves the page is Python, so one package holds the store layout, the server and the publisher: one implementation of the layout, no parity test between a JS publisher and a Python reader. `pip install annals` works wherever an agent runs.

**Deployed with the platform; the content never is.** On the owner's host annals is an ordinary app: the platform installs the package, mounts the API, serves the page shell and gates both with its login, like every other app. The documents live in the data root (`~/.local/share/annals`), outside the app directory, and are written there directly by `annals publish`, so a new document never triggers a deploy, a deploy never touches a document, and a broken document cannot take the platform down. The first version ran as a separate service to get that independence; it was the content, not the code, that needed it.

**Media are documents.** An image, a video, audio or a PDF shows inline; a folder is one document, shown as its page (when it has one) or as a gallery. Files are served with `FileResponse`, which streams and answers byte ranges, because a video that cannot seek, or that Safari refuses to play, is not shown at all. Thumbnails are made on first request and cached next to the documents, so a folder of two thousand renders loads on a phone.

**A file write is the publish operation.** Publishing is `rsync` (or a local copy) into the directory the server reads; there is no ingest API and no token to manage. The read side can therefore stay behind whatever login already protects the host, and a annals never becomes a way to post without credentials. An ingest endpoint is seam 1's declared replacement, not a v1 feature.

**Flat with tags and groups.** Agents from many projects do not share a hierarchy, and every placement decision costs tokens. A group is a titled, ordered list of document ids with its own URL, which is the "one link for a set of documents" an agent needs when it has produced several.

**Time-sortable, readable ids.** `YYYYMMDD-HHMMSS-<slug>-<4 hex>`: a directory listing is in publication order, a URL says what it points to, and two publishes in the same second cannot collide.

**Plain files, no index.** The same tree is written by rsync from another machine and read by the server. An index would be a second source of truth to keep consistent across that boundary; listing a few hundred `meta.json` files is cheap.

**The page has no build step.** It is one html shell, one stylesheet and one script, served by the package; a host keeps only the shell (two paths), so the page upgrades with the package. The page is a thin viewer over a small JSON API, phone first; a bundler would be the only build in the deployment. If the page grows a second surface (editing, comments), it moves to the usual schema-driven stack.

**Markdown renders in the browser, html in a sandboxed frame.** Rendering client-side keeps the server free of a markdown dependency and makes the source toggle trivial (the same text). An html document is the agent's own code, so the frame cannot read the annals's cookies or call its API (`Content-Security-Policy: sandbox ...` on the raw response plus the frame's `sandbox` attribute).

**Other folders are read, never written.** A folder source (the crowsnest ledgers) belongs to whoever writes it. annals walks it on each listing (a stat per file; a file is re-read only when its size or mtime changed), never copies it, and never writes into it; the owner's tags on its items live in annals' own data root. A source is anything with `rows`, `item` and `text` (`annals.sources.Source`), so a new kind of folder is a new class at the `sources=` seam.

**One list, every source.** Each source yields rows of one shape (`key` = `<source>:<id>`, `title`, `kind`, `session`, `time`, `size`, `tags`, `excerpt`), so search, filters, sorting and tagging are written once. Full-text search runs on the server (the page never downloads the texts); facet counts run in the page over the rows a search returned, so a toggle costs no round trip and every count is the one that choice would give (a family's own selection is left out of its counts: OR within a family, AND across).

**Tags apart from items.** The owner's tags are an overlay keyed by item key: an entry, once written, is the item's whole tag list, so a publisher's tag can be removed too, and deleting the entry falls back to the item's own. One JSON file, written atomically, re-read when another process changed it; a database replaces it at the `tags=` seam.

**No title that says nothing, and the owner renames (2026-11-22).** The owner found several audio overviews all titled "overview" and no way to rename them. Two makers (podpatch, hailing) write `<folder>/overview.mp3`, and annals titled a file by its name. A name in `annals.titles.GENERIC_STEMS` (overview, output, index, final, ...) now takes its title from beside the file: the `title` of a manifest the maker wrote (`TITLE_FILES`), else the folder's name without its date stamp and hash, else the name after all. This is fixed in annals, the one place every publisher passes through, rather than in each maker. Rename is a write to the document's meta (`title`, plus `renamed`, the time), not an overlay like tags: the title feeds search, shares, exports and the Audio tab, and one field read everywhere is simpler than an overlay consulted in each of them. A replacement keeps a renamed title, so a publisher's next version does not undo the owner's choice. Page: a pencil beside the title of a document or group, editing in place (Enter saves, Escape cancels); API `PATCH /docs/{id}` and `PATCH /groups/{gid}` with `{"title"}`, same-origin, and outside a room's routes; CLI `annals rename`.

**The sessions that made a document: one row under its title, owner only (2026-11-22).** The owner asked for a link that opens the session or sessions that made a document, removed when the document is shared, "in a structured consistent place", leaning to the end. It is the top, not the end: the row under the title is drawn by annals for every kind (markdown, an html page in a frame, a PDF, an image, a folder), so it is always in the same spot and in sight on a phone, whereas the end of an html page or a PDF is inside the document, out of annals' reach, and far down a long report. The links are meta (`sessions`: `[{name, url}]`, `annals.sessions`), never text in the document: the publisher records the claude.ai link of the Claude Code session it runs in (`CLAUDE_CODE_BRIDGE_SESSION_ID`), a new version adds its session after the earlier ones, and a group shows its documents' sessions. Removal is structural: a share and a room show allowlists of meta fields that do not name `sessions` or `source`, `copy` to a room drops provenance, and the page draws the row for neither, so no filter over prose is needed and none can miss one. Rejected: a footer appended to the document's text (sharing would have to strip it from markdown, html and exports alike, and a PDF could not be stripped at all). A document keeps at most twelve sessions (the first and the latest), and the page shows the first and the latest two with "+k more". The default link is the session the command runs in: a long-lived process (an `annals mcp` server, a background job) carries the link of the session that started it, so such a caller passes `session_url`. `ls --session` finds a document by any session that made a version of it. Deploy the server before the publishers: an older server applying a newer replacement keeps only the newest session.

**A share link's page is its text, with no script (2026-11-16).** The page a share link opened was a shell the viewer's script filled, with an html document in a frame. NotebookLM made a twenty-minute audio overview of such a link from its title alone. A test showed its fetcher runs script: it read the viewer's buttons, but not the framed document, and a group shows only titles. So text put in the shell for script-less readers would not have been enough: the script replaces it. The page is now rendered on the server with the shared text and nothing that runs (`annals.share_page`, built on the notebook sources' renderer and `combine.html_body`, so the rules for what a share may show stay in one place). A document that is an html page is served as itself at its link, filtered and sandboxed as `/raw` serves it. The script viewer stays at `?viewer`. The owner's words were that a person "only needs to see the actual doc (so no need for a layer of JS on top)". The same link also answers as `share.md` and `share.pdf` (the existing combined export, under names a reader recognises), named in `<link rel="alternate">` and printed by `annals share`. Rejected: separate "link to md" / "link to pdf" shares, which would mean three records to revoke and a choice made before knowing who will read it; and text in the shell under the viewer, which a fetcher that runs script never sees. Server-side HTML to PDF of an html document stays out (no Chromium on the host, WeasyPrint is lossy), so an html document reaches the PDF as its words and structure.

## The machine contract

Other packages call the CLI and parse what it prints, so two shapes are a contract, changed only by adding keys. Everything else (`show`, the page's JSON, `meta.json`) may change.

- `annals publish ... --json` (any command takes `--json`): the result dict on stdout and nothing else; warnings and notes stay on stderr. One document: `{id, title, url}`; with `--group` or `--add-to` also `group_id`, `group_url`; several paths: `{docs: [{id, title, url}, ...]}` (plus the group keys). Without `--json`, a person gets bare links.
- `annals publish --meta key=value ...` writes `source`, beside `host`, `cwd` and `session`. By convention `corpus`, `repo`, `issue`, `item`, `kind` (the docstring of `annals.tools.publish` is where they are written down); other keys are kept.
- `annals ls`: `{docs: [{id, title, kind, tags, created, updated, source, url}], total}`, newest first. `--since` (ISO date or time, or an age such as `6h`, `2d`), `--session`, `--tag` and `--meta key=value` match whole values, not substrings, and all must hold; `--since` counts a replaced document from its newest version (`updated`). `GET /docs` takes the same filters (`since`, `session`, `tag`, repeated `meta=key=value`; a bad value is a 422, a time with no offset is the server's local time, so send `Z` or an offset) and returns `{docs}` without `total`. `total` counts matches before `--limit`, so a poller that sees `total` above its `--limit` raises the limit. Each row's `source` may carry `session_url` (the claude.ai link of the publishing session: owner-only, so do not paste `ls --json` into a public issue). Meta values are always strings; `publish --meta` cannot set `host`, `cwd`, `session` or `session_url`; `ls --meta` may filter on them. `ls` prints JSON with or without `--json`. A failure is exit code 1, empty stdout and one line on stderr. `--since` is the feed to poll: no webhook or event bus.

## The overview engine contract

annals owns the request queue, the daily limit, the progress relay and the heard-spans arithmetic; it does not know how audio is made. That is a command (`ANNALS_OVERVIEW_COMMAND`, or `annals listen-work --command`), and this is everything annals promises it and expects of it. `tests/test_overview.py` pins it (`test_the_engine_contract`, `test_the_engine_failure_contract`, `test_a_long_failure_reason_is_cut`, `test_a_command_must_name_source_and_out`, and the older tests of the worker and of the down rule).

- **Inputs.** The command is split like a shell line (`shlex`, no shell: no pipes, no `$VAR`), then each argument is filled with `str.format`, so a literal brace must be doubled. The placeholders are `{source}`, `{minutes}` (the length asked for, as a string: 3, 5 or 7), `{out}` and `{url}` (the source document's page, to link back to; the bare document id when the worker is not given a way to build the address). The command must name `{source}` and `{out}`, a bad placeholder is refused before any money is spent. `{source}` is a UTF-8 Markdown file: `# <title>`, a blank line, the document's text (html is reduced to text first; for a combined request, the combined document). The command runs in a fresh scratch directory that holds only `source.md` (and where `{out}` points) and is deleted afterwards, inheriting the worker's environment, with stdin on `/dev/null`, in its own process group.
- **Output.** One non-empty file at `{out}`, an HTML page (the audio player and its text); only "non-empty" is checked. annals publishes it as a document of its own.
- **Exit status.** 0 means success *and* a non-empty file at `{out}`. Exit 0 with no page is a failure, whatever the command printed ("the overview command wrote no page"). A non-zero exit is a failure.
- **On failure** the last non-empty line of the command's output (stdout and stderr together) is shown to the reader, cut to 300 characters, so it must be one sentence a person can read ("the voice account is out of credit"). With no output, "the overview command exited N". A run still going after `DFLT_TIMEOUT_S` (30 minutes) is stopped (SIGTERM to the group, 5 seconds, then SIGKILL) and reads "gave up after N seconds". After a normal exit annals sends SIGTERM to the whole group too: an engine must not leave a background process behind.
- **Down.** The same failure (compared with digits and hex ids removed) from `DOWN_AFTER` (2) different documents, each within `FAST_FAILURE_S` (120) seconds, marks the maker down: requests wait instead of failing or spending the daily limit, the page says why, and one request is tried again every `PROBE_EVERY_S` (3 hours); the first success, or `annals listen-down --clear`, clears it. Only the command's own failures count (not a timeout, and not a document that cannot be spoken).
- **Not part of the contract.** Which model or voice is used, what the command costs (annals only counts starts: at most `ANNALS_OVERVIEW_DAILY_LIMIT`, 20, in 24 hours), anything it prints on success. annals does not parse any engine's own output format: an engine that answers in JSON must put its reason in the last line itself. (`annals.overview._readable` still unwraps the `claude -p` JSON envelope for the engine in use today; it goes when that engine honours the last-line rule, thorwhalen/hailing#15.)

## Ledgers from several machines

Ledgers are written on several machines, and annals reads one folder per source, so the copies have to meet in one place. Each machine's scheduled `crowsnest publish` pushes its whole ledger folder into its own mirror on the server, `~/.local/share/crowsnest/ledger-hosts/<machine>/` (crowsnest's `[ledgers] mirror`: `rsync -a --update`, never `--delete`; a local copy on the server itself). The host lists the parent as one source, `FolderSource(ledger_hosts, name="ledgers", session_of=...)`, whose `session_of` reads the session from the path below the machine's folder (`laptop/lookout.md` -> `lookout`), so equal names on two machines never overwrite each other and a ledger's page is `/i/ledgers/<machine>/<name>.md`. Nothing in annals changed for this: `session_of` was already the seam. crowsnest flags a ledger that has not reached its mirror (`crowsnest ledger --stale`, and a `!!` line on its roster). Reading the other machines live over ssh was the alternative, and a worse one: a closed laptop would empty the list.

## Where the data lives

`~/.local/share/annals/{docs,trash,groups,tags}`, plus `cache/thumbs` (derived, safe to delete); `ANNALS_DATA_DIR` overrides the root. Folder sources stay where their owners keep them. Nothing under the package or any app directory holds documents.

## Trust boundary

`meta.json` is written by the publisher, so the server does not trust it to keep paths in bounds: a raw or thumbnail request must name a file the meta lists AND resolve inside that document's directory (symlinks included). Every raw response except PDF carries `Content-Security-Policy: sandbox`, because the page shares its origin with every other app on the host and a browser renders more types as documents than any list would name. Markdown is rendered in the page, so marked's output always goes through DOMPurify first.
