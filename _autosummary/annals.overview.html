annals.overview#

Spoken overviews of a document: the request a page makes, and the worker that fulfils it.

A reader asks for an overview from a document’s page. That writes one small JSON file under the data root (overviews/<doc id>.json). A worker on the same machine reads the document from the store, runs a command that makes the overview, and publishes the result as a document of its own. The page polls the request’s state.

annals does not know how an overview is made. The command is the seam: any program that takes a text file and writes one HTML page, named in ANNALS_OVERVIEW_COMMAND or passed to work(), with {source}, {minutes} and {out} filled in:

my-overview {source} --minutes {minutes} --player-to {out}

The feature is off unless the host turns it on (mk_api(overviews=True)), because making an overview spends money. For the same reason, a current overview is not made again unless forced, a crash after publishing does not pay twice, work stops at a daily limit, and a request nobody fulfilled expires rather than spending money whenever a worker next wakes.

Run the worker on a timer. Finished request files stay in the folder and the worker writes there, so a watcher on the folder would keep waking it.

>>> html_to_text("<title>x</title><p>One &amp; two</p><script>no()</script><p>Three</p>")
'One & two\n\nThree'
>>> [c["characters"] for c in choices()]
[2700, 4500, 6300]
