annals.search#

How the catalog answers a query: the search strategies.

A strategy is a callable (query, rows, text_of) -> rows: given every listed row (the catalog has already listed them and overlaid the owner’s tags) and a way to get an item’s full text, it returns the rows that match, best first, each with a snippet of the text around the match and, when it ranks, a score (higher is better). The catalog takes one as its search keyword (annals.catalog.Catalog), so a smarter one (semantic, hybrid, an agent that rewrites the query) plugs in at the same place.

Two ship here:

  • IndexedSearch, the default when the data root is on this machine: a SQLite FTS5 index kept on disk (cache/search/index.sqlite under the data root). Each query brings it up to date first, re-reading only items whose stamp changed (their listed fields, and the stamp a source gives, else their time and size), so the first query after a restart costs one pass over the texts and every later one a few milliseconds. Matching is by word prefix with English stemming (rate finds “rates” and “rated”, not “separate”), every word required, ranked by BM25 with the title weighted most.

  • scan_search(), the index-free fallback (a remote data root, tests): every word must appear as a substring of the title, tags, session, excerpt, id or full text; newest first, as listed.

Bases: object

A SQLite FTS5 index of every row’s fields and text, synced per query by stamp.

path is the index file (made on first use; ":memory:" keeps it in memory). weights are BM25’s per-column weights (title, tags, session/id/source, excerpt, text). max_results caps a ranked answer; the best snippet_rows carry FTS5’s snippet, the rest a cheaper window of text around the query’s longest word. Safe across threads (one sync at a time: queries that arrive during a sync wait for it rather than redo it) and across processes sharing the file (two web workers): every write is one short BEGIN IMMEDIATE transaction. If the index fails (a locked or damaged file), a query falls back to scan_search() rather than fail.

annals.search.fts_query(q)[source]#

A user’s words as an FTS5 query: every word required, each a prefix.

Each word is quoted, so FTS5 syntax typed by the user (AND, -, :, quotes) is searched for as text, never run as an operator. Control characters are dropped, and so is a word with no letter or digit (the tokenizer would drop it anyway, and an empty phrase matches nothing), so a query of only punctuation is no query.

>>> fts_query('data rates')
'"data"* "rates"*'
>>> fts_query('a"b NOT')
'"a""b"* "not"*'
>>> fts_query('  ... - *')
''
Return type:

str
