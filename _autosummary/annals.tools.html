annals.tools#

The operations, as plain functions: JSON-able arguments in, JSON-able dicts out.

This module is the single source of truth for what a annals can do. The CLI (annals.__main__, via cw), the MCP server (py2mcp over string refs to these names) and the shipped skill all describe the same functions, so there is nothing to keep in parity. Nothing here prints or exits; the surfaces do that.

annals.tools.aggregate(group_id, *, demote=1, order='numbered', no_toc=False, keep_wraps=False, target=None, to=None)[source]#

Every markdown file of a group as ONE markdown document, printed (nothing is stored).

group_id is a group’s id or link. The document has the group’s title, a table of contents, then one ## section per file named after its path (a folder document’s files under its title). order: numbered puts paths that start with a number first, numerically, the rest in the group’s order; given keeps the group’s order. demote pushes each file’s headings that many levels down (0: as written). Hard-wrapped lines are joined unless keep_wraps; no_toc leaves out the table of contents. Redirect to save it: annals aggregate <id> > bundle.md.

Return type:

str

annals.tools.configure(*, target=None, base_url=None, to=None, outbox=False, share_base_url=None)[source]#

Write the publisher config (where to publish, what link to print) and show it.

Example

annals configure --target tw:/root/.local/share/annals --base-url https://apps.example.com/annals. --to NAME saves the target and base url as a named target (annals publish --to NAME) and leaves the default alone. --outbox marks the target as an outbox: a directory the server pulls and empties (it cannot be written to from here), so replacements are left for the server to apply; it is kept by later changes (ANNALS_OUTBOX=0 or an edit of the file turns it off). --share-base-url is where share links point when the share server is not at <base-url>/shared (a platform running it as its own public app). With no arguments, shows the resolved settings without writing.

Return type:

dict

annals.tools.copy(refs, *, to, source=None, target=None, base_url=None)[source]#

Copy documents or groups to a named target, keeping their ids; print the new link.

refs are links (https://.../annals/d/<id>, .../g/<group-id>) or bare ids; only the id is used, so the link may point at any instance. They are read from the default target (or the named target source) and written to the named target to. A group is copied with its documents and keeps its id and title. Copying again refreshes the copy. The source must be readable from this machine (a directory, or host:/path). target/base_url override the DESTINATION’s location, as in publish.

Return type:

dict

annals.tools.page_shell(*, api='/api/annals', base='/annals', title='annals')[source]#

The page’s html shell, for a host that serves the API under its own prefix.

An enlace app writes it once as its frontend: annals page-shell --api /api/annals --base /annals > frontend/index.html. The shell only names the two paths; the page’s code loads from the API, so it upgrades with the package.

Return type:

str

annals.tools.publish(paths, *, title=None, tags='', group=None, add_to=None, session=None, all_files=False, target=None, base_url=None, to=None, replace=None, artifact=None)[source]#

Publish one document and print its link; several paths become several documents.

paths: files of any kind (markdown, html, images, video, audio, pdf, text), a directory (one document: an index.html or single page with its assets, else a gallery of everything in it), or - for stdin (markdown). tags is comma separated. group names a group to create from the published documents; the reply then carries group_url too. add_to appends them to an existing group instead (its id, as printed in a group link), so a second batch lands under the link the owner already has. session records who published (the source shown on the page). A directory skips hidden files and caches (.*, __pycache__, *.pyc) unless all_files. to publishes to a named target of the config file ([targets.NAME], see annals configure --to) instead of the default one. replace (a document’s link or id) publishes ONE path as a new version of that document: the link stays the same, the page shows the new version and offers the earlier ones. That is how a living page (a guide, a status page) keeps one link. artifact (a claude.ai artifact link) is the interactive version of the page: the document’s page shows an “Open the interactive version” button. Publish the Artifact first, then the same page here with its link.

Return type:

dict

annals.tools.serve(*, host='127.0.0.1', port=8765, data_dir=None, base_path='/annals', allow_open=False)[source]#

Serve the annals page and API (needs pip install 'annals[server]').

Auth comes from the environment: ANNALS_WHOAMI_URL + ANNALS_ALLOWED_USERS to sit behind an existing login, ANNALS_BASIC_USER + ANNALS_BASIC_PASSWORD for HTTP Basic, nothing for an open server on localhost. A host reachable beyond this machine with no auth configured is refused unless allow_open (--allow-open) says something else gates it.

Return type:

None

annals.tools.share(ref, *, password=None, expires='7d', include=None, exclude=None, title=None, target=None, base_url=None, to=None)[source]#

Make a public link to ONE document (or group) and print it; nothing else is reachable.

ref is a document or group id, or its link. The link opens without a login, shows only that page and the files chosen, and can be revoked (annals unshare). include: comma separated files of the document to share (the page itself always is), or ids of other annals pages it links to; by default every file of the document (for a group: every document; include then picks documents). exclude drops files. expires (7 days unless told): 12h, 30d, 2w, a date (2026-11-01, through that day, UTC), an ISO time, or never. password gates the link (stored hashed; - reads it from stdin, so it stays out of the shell history).

Return type:

dict
