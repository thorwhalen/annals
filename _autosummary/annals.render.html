annals.render#

Render markdown (and other page-like files) to html and PDF, with their images inside.

No web framework in here, so the CLI can use it as the server does. The PDF is made by WeasyPrint from markdown-it’s HTML (raw html in the markdown is shown as text, never interpreted). Images are embedded; audio, video, other PDFs and files become a visible link to the resource, so the reader can open or play it. WeasyPrint is imported on first use; a missing one is a annals.requirements.MissingDependency with the install hint.

Nothing is fetched from the network: an image outside the document is a link, never loaded. Everything WeasyPrint is allowed to load is a placeholder url (annals-file:N) for bytes this module already holds (Embedded).

Module Attributes

PDF_IMAGE_MAX_PX

longest side of an embedded image; a 6000 px render is shrunk, a phone screenshot is not

PDF_IMAGE_MAX_BYTES

an image larger than this on disk is linked, not embedded

PDF_IMAGE_MAX_PIXELS

an image with more pixels than this is not decoded to be shrunk (a small box would run out of memory)

PDF_IMAGES_TOTAL_BYTES

all embedded images of one PDF together

PDF_MAX_TEXT_BYTES

markdown larger than this is not made into a PDF (rendering cost grows faster than size)

annals.render.markdown_to_html(text, *, rel, files, open_file, file_url, embedder=None, read_bytes=None, list_unreferenced=True)[source]#

The html body of the markdown text (the file rel of a document) and its images.

Images the document holds are embedded (placeholder urls in the returned Embedder); other files become links, shown as media rows; external images are never fetched. Raw html in the markdown is text, not markup. read_bytes(rel) reads an image the way the caller allows (a share filters svg text); list_unreferenced=False leaves out the “More in this document” rows (when the document’s other files are sections of a combined output of their own).

Return type:

tuple[str, Embedder]
