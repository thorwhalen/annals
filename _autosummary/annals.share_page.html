annals.share_page#

A share link’s page with its text in it, and no script, so every reader can read it.

A share link used to answer with a shell: a <title> and an empty <div> that the viewer’s script filled, with an html document inside a frame. NotebookLM made a twenty-minute audio overview of such a link’s title. Its fetcher does run script, so it saw the viewer’s buttons, but a group shows only titles there and a frame is not read. So the page a link opens is now the shared text itself, rendered on the server under the rules every shared text already follows, and nothing on it runs. The owner asked for exactly that: a person only needs the document. The script viewer (galleries, players, downloads) is one link away, <link>/?viewer.

The same share also answers as one Markdown file and one PDF, with the same token, expiry and revocation (the routes are annals.share_api’s); the page names them in <link rel="alternate"> and in a line at its top:

<link>/                 the page: every shared document's text (a group's, in order)
<link>/d/<id>           the page of one document of the share
<link>/share.md         the whole share as one Markdown file
<link>/share.pdf        the whole share as one PDF (images included)
<link>/d/<id>.md|.pdf   one document of it
<link>/?viewer          the script viewer, as before

What goes in the page, per document: its markdown and html files (the notebook sources of annals.notebook, numbered files first), markdown rendered with links and images made safe by annals.notebook.render_source_body(), html reduced to its structure and words by annals.combine.html_body() with a link to the page as designed; for a document with no text, its images; its audio and video with the browser’s own players; then links to its other files. Past STATIC_MAX_BYTES of text or STATIC_MAX_FILES files, the remaining files and documents are links to their own pages, so a large group still answers quickly and every document stays reachable. A document that is an html page (designed_page()) is served as itself at its own link, filtered and sandboxed as /raw serves it, with a <base> (with_base()) so its images and styles load.

Module Attributes

STATIC_MAX_BYTES

the page's text stops growing past this many bytes of html; later documents are links

STATIC_MAX_FILES

the text files rendered into one page at most; the rest are links (a page is made on every request, and anyone holding the link may make one)

STATIC_FILE_MAX_BYTES

a document's file larger than this is linked, not put in the page

STATIC_MAX_IMAGES

images shown for a document without text (a gallery folder); the rest are listed

STATIC_MAX_PLAYERS

Bases: object

What a page of one share may show and link to.

link is the share’s address (root-relative is fine: a fetcher resolves it against the page), shared_ids the documents it includes, root_id its group ("" for a document share), private_hosts the owner’s hosts, never linked to.

annals.share_page.designed_page(meta, files)[source]#

The html file a document’s page is, when it is one, else None.

Such a document is served as itself at its link (filtered and sandboxed, as /raw serves it): a person sees it as designed, and a fetcher, even one that runs script, reads it at the top level rather than inside a frame it does not open.

Return type:

str | None

annals.share_page.page_body(docs, *, title, read_text, scope, doc_id=None, viewer_url=None, max_bytes=None)[source]#

The page’s content and its description: (html, plain text of ~280 chars).

docs are the (meta, files) pairs to show, in order (one, for a document’s page); read_text(doc_id, rel) reads a file as it is on disk (the shared-text filters are applied here). doc_id names the document a /d/<id> page is for, which picks the alternates the page offers; viewer_url is where the script viewer opens it. max_bytes: STATIC_MAX_BYTES.

Return type:

tuple[str, str]

annals.share_page.with_base(page, href)[source]#

page with <base href> as its first element, so its relative references (images, styles, its other pages) resolve where the share serves its files.

The page’s own <base> and referrer <meta> go: either would send its requests, or the link, elsewhere. The tag goes right after the doctype, where the parser puts it in the head whatever comes later (a <head> written in a comment, say).

Return type:

bytes
