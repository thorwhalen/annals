annals.catalog#

The catalog: every source’s items as one list, with search and the owner’s tags.

Catalog is the facade the HTTP API stands on. It combines named sources (see annals.sources) and a tag store (see annals.tags):

  • Catalog.rows() lists items newest first, across sources or within one, filtered by a full-text query (every word must appear in the title, tags, session, excerpt or full text; case-insensitive), each row with the owner’s tags overlaid and, when there is a query, a snippet of the text around the first match.

  • Catalog.item() is one item, Catalog.set_tags() replaces its tags (in the tag store, never in the item), Catalog.tag_counts() lists every tag in use.

Facets (kind, session, date, tag) are not computed here: the page counts them over the rows it received, so every toggle is instant and the counts are always the ones the current query would give.

annals.catalog.mk_catalog(store, *, sources=None, tags=None)[source]#

The published documents first, then the extra sources; the owner’s tags beside them.

sources maps a name to a folder path (read in place) or a Source; by default the folders named in ANNALS_SOURCES. tags defaults to one JSON file under the data root (tags/tags.json), or a dict when the data root is remote. The API, and any CLI or agent tool that tags items, build their catalog here.

Return type:

Catalog
